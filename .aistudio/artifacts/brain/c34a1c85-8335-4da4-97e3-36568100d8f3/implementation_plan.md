# BLE 空间概率粒子寻物雷达 — 深度全审报告与平台极限演进方案

本方案基于对当前已交付代码库的逐行深度审计，结合 Android 原生硬件物理极限与 Google AI Studio 云端构建/模拟器环境边界，自主制定出一套将系统推向 **L4+ 工业级无线电测向与空间概率定位极限** 的完整升级蓝图。

### User Review & Critical Decisions

> [!IMPORTANT]
> 按照您的授权，我已直接从系统架构师视角承担全部技术决策责任，完成对现有 6 大模块的代码审计与极限演进规划，无需您回答任何技术问题，确认后即可一键执行升级。

- **决策 1（突破单均值陷阱 — 双峰对称破缺与主峰锁定）**：用“空间网格密度寻峰 + 主簇加权质心（Mode-Seeking Cluster Centroid）”替代原本的单纯全局加权均值，彻底解决直线行走时左右镜像对称粒子团导致准星落在中间空白区的数学缺陷。
- **决策 2（原地转身破除镜像 — 人体躯干遮挡方向性衰减模型）**：在粒子似然函数中引入基于用户平滑朝向角 `azimuthRad` 的 2.4GHz 人体遮挡方向性衰减修正（后向扇区附加衰减），支持用户“原地缓慢旋转 360°”即可利用信号强弱差辅助破除方位模糊。
- **决策 3（真·零 GC 双缓冲乒乓快照池）**：消除 `MonteCarloParticleEngine.buildSnapshot()` 中每次更新调用 `.copyOf()` 产生的原生数组分配，改用预分配 A/B 双缓冲乒乓快照对象池，实现 60fps 下 100% 零堆内存分配。
- **决策 4（广播协议深度拆包与 Room 设备校准黑匣子）**：新增 iBeacon、Eddystone (UID/TLM)、Apple Continuity 与 Google Fast Pair 原始字节流深度解析器，并启用本地 Room 数据库持久化保存每台设备的专属校准 `TxPower`、环境衰减指数 $n$ 与历史寻物复盘记录。

### 1. 现有代码库深度全审报告（Codebase & Platform Limit Audit）

#### 1.1 现有实现已达标的工程基石
- **防熔断与权限边界（契约 1）**：`BleScannerManager` 已严格实现 API 31+ (`BLUETOOTH_SCAN`/`CONNECT`) 与旧版定位权限分流、`5000ms` 启停冷却锁以及 `txPower == 127` 异常值拦截。
- **PDR 传感器降级链（契约 2）**：`PdrSensorEngine` 已实现 `sin/cos` 指数移动平均（$\alpha=0.2$）消除 $\pm 180^\circ$ 跳变，并具备 `TYPE_STEP_DETECTOR` $\rightarrow$ 三轴加速度模长峰值（$>11.5\text{ m/s}^2, 350\text{ms}$）$\rightarrow$ 虚拟十字键三级降级。
- **L2 卡尔曼与 L4 SoA 粒子框架（契约 3~5）**：7 窗口 Hampel 抗尖峰 + 1D Kalman 滤波、2500 粒子扁平数组、距离下限 `0.15m` 钳制及 95%+5% 环状重采样均已稳定运行。

#### 1.2 深度审计揪出的 5 处隐蔽缺陷与性能瓶颈
1. **全局加权均值的“双峰镜像陷阱”（数学缺陷）**：
   - *现状问题*：在 `MonteCarloParticleEngine.kt` 第 224-228 行，目标估计坐标 `(estTargetX, estTargetY)` 直接对全部 2500 个粒子求加权平均。当用户仅沿单一方向直线行走时，真实目标左右对称位置会出现两个等权重的粒子团（双峰分布），全局均值会错误地指向两个粒子团连线中点（即用户脚下轨迹线上），直到用户拐弯后才缓慢收敛。
   - *极限修复*：引入 $16 \times 16$ 空间概率密度网格（Spatial Density Grid），实时检索权重密度最高的“主概率峰（Primary Mode）”与“次级镜像峰（Ghost Mirror Mode）”。主准星锁定最高密度簇质心，同时在雷达上用虚线幽灵准星标出次级候选峰，并动态给出**“最佳下一步走位建议箭头（Optimal Orthogonal Step Hint）”**指导用户向垂直方向迈步以瞬间消灭镜像峰。
2. **快照导出的隐式数组拷贝（内存微抖动）**：
   - *现状问题*：`MonteCarloParticleEngine.kt` 第 264-267 行每次生成 `ParticleSnapshot` 时调用了 `snapX.copyOf()` 等 4 次数组克隆，在 5Hz 广播 + 连续步进下每秒仍产生约 80KB 临时数组对象。
   - *极限修复*：构建预分配的 **A/B 双缓冲乒乓快照池（Ping-Pong Snapshot Buffer）**，配合单调递增的 `version: Long` 状态戳，实现全程零 `new FloatArray` 分配。
3. **PDR 动态步长固定化（航位推算累积误差）**：
   - *现状问题*：`PdrSensorEngine.kt` 在优先级 B（加速度计计步）与优先级 A 下均采用固定步长 `0.65m`。但真人快走与慢走步幅差异可达 $\pm 35\%$。
   - *极限修复*：集成 **Weinberg 非线性步长估计算法**（$\text{StepLength} = K \cdot \sqrt[4]{a_{\max} - a_{\min}}$），根据每一步的垂直加速度峰谷差动态推算实时步长（范围钳制在 `0.42m ~ 0.92m`），大幅降低 PDR 轨迹漂移。
4. **单文件体积超标与架构解耦（可维护性瓶颈）**：
   - *现状问题*：`RadarViewModel.kt`（527 行）、`TrackerScreen.kt`（659 行）、`ScannerScreen.kt`（532 行）体积偏大，沙盒物理引擎与视图模型耦合。
   - *极限修复*：拆分为独立职责模块（沙盒多径信道模拟器、协议字节拆包器、L2/L4 实时波形示波器组件、Room 校准仓库），确保每个源码文件精简高内聚。
5. **平台与物理硬件的客观极限边界（What Can vs. Cannot Be Done）**：
   - *物理与平台不可逾越的边界*：
     1. 云端模拟器无真实 2.4GHz 射频前端与 UWB/蓝牙 6.0 HADM 相位测距硬件，无法在云端模拟器上直接捕获真实物理房间的蓝牙电磁波；
     2. 标准 BLE 4.0/5.x 广播帧不包含 AoA/AoD 到达角天线阵列相位差数据，单点静止状态下单靠全向 RSSI 只能确定“距离环”而无法直接解算绝对角度。
   - *软件算法可榨干的最高极限*：
     1. 利用 **人体遮挡方向增益模型（Body Shadowing Model）** + **原地旋转扫描**，即便不迈步也能通过手机朝向旋转引起的 $4\sim 7\text{ dB}$ 阴影衰落初步打破圆环对称；
     2. 在沙盒中引入 **可交互的 2D 墙体/多径障碍物（NLOS 混凝土墙、玻璃隔断、金属反射源）**，完整复现真实室内穿墙衰减与非视距偏差，验证粒子群对环境衰减因子 $n \in [1.8, 4.0]$ 的自适应联合估计能力。

### 3. 核心架构决策与技术权衡（Key Decisions & Trade-Offs）

- **决策 A：空间密度网格寻峰（Grid Mode-Seeking） vs. 全局加权平均**
  - *选定方案*：在 $[-15\text{m}, +15\text{m}]$ 活动区域内划分零分配的二维密度直方图，定位权重最集中的主峰窗口并在窗口内计算局部加权质心，同时识别次高峰计算双峰分离度（Bimodality Index）。
  - *理由*：复杂度仍为 $O(N)$（仅需一次遍历），零额外内存分配，却能彻底消除多模态对称分布下的均值失真问题。
- **决策 B：本地 Room 数据库存储校准档案与复盘日志**
  - *选定方案*：使用 Jetpack Room + KSP 建立本地 SQLite 数据库（包含 `CalibratedBeaconEntity` 与 `RadarHuntSessionEntity`）。
  - *理由*：BLE 硬件参数校准与本地射频测向复盘属于纯设备端硬件配置与遥测缓存，使用 Room 可实现零延迟离线持久化，无需强制用户登录云端账号。

#### 核心交互与状态流转映射
1. **双峰检测与走位引导闭环**：每次 `MonteCarloParticleEngine.stepUpdate()` 完成后，同步输出主峰坐标 `(estTargetX, estTargetY)`、次级镜像峰坐标 `(secondaryX, secondaryY)`、双峰权重比 `bimodalRatio` 以及正交破缺建议方向角 `recommendedStepRad`，驱动 `TrackerScreen` 渲染战术走位箭头。
2. **NLOS 穿墙沙盒闭环**：用户在追踪舱切换室内障碍物预设（无遮挡 / 单承重墙 / 多隔墙走廊）时，沙盒引擎实时计算每台虚拟信标与用户连线同墙体线段的几何交点，自动叠加 `4.5dB ~ 8.0dB` 穿墙损耗，并在 2D 雷达上高亮显示被墙体遮挡的射线。
3. **设备专属校准与寻物日志持久化闭环**：用户在校准面板调整某台设备的 `TxPower`、环境衰减指数 $n$ 或自定义别名并点击“保存校准档案”时，通过 `RadarCalibrationRepository` 写入 Room 数据库；下次扫描到同一 MAC 地址时自动加载已校准的射频参数。
